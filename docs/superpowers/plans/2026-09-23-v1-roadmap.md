# GTNH Development v1.0 Roadmap

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver GTNH Development v1.0 through eight buildable, tested, reviewable milestones.

**Architecture:** Implement one milestone at a time. Services aggregate results; providers understand syntax and repository patterns. Long-lived state uses smart pointers, and compatibility differences remain behind `compat` adapters.

**Tech Stack:** Kotlin 2.x, Java 21, IntelliJ Platform Gradle Plugin 2.x, IntelliJ PSI, Gradle External System, Minecraft Development.

**Spec:** `docs/superpowers/specs/2026-09-23-gtnh-development-v1-design.md`

## Global Constraints

- Support IntelliJ IDEA 2025.1 through 2026.2 (`251` through `262.*`).
- Keep `com.demonwav.minecraft-dev` required in Gradle and `plugin.xml`.
- Never add repository-specific production identifiers.
- Never perform project-wide search, Gradle lookup, or Git work on the EDT.
- Store long-lived PSI references through smart pointers or stable identifiers.
- Do not advance while current milestone compilation or tests fail.

## Review Focus

- Broken or unresolved PSI must return partial/empty results without exceptions; covered by v0.3 and v0.4 fixtures.
- Multi-module scope must not silently exclude valid results; covered by v0.3 and v0.9 fixtures.
- Unsupported IDE/Minecraft Development combinations must fail verification clearly; covered by v0.9 CI.
- Cancellation must stop long searches without partial-state corruption; covered by v0.3, v0.4, and v0.9 tests.
- Human-only contribution claims must remain unchecked unless explicitly confirmed; covered by v0.7 tests.
