# v0.7 Pull Request Assistant Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Provide read-only contribution diagnostics, executable discovered checks, human-confirmed checklist items, and truthful editable PR drafts.

**Architecture:** Git and Gradle adapters produce facts. `GtnhContributionService` combines facts without mutating repositories. `GtnhPrDraftService` renders only observed or user-supplied information.

**Tech Stack:** Kotlin, Git4Idea public APIs, dynamic Gradle task service, JetBrains UI components.

**Spec:** `docs/superpowers/specs/2026-09-23-gtnh-development-v1-design.md`

## Global Constraints

- No automatic PR submission.
- No invented test results, issue links, or human-only claims.
- No automatic remote or branch mutation.

## Review Focus

- Detached HEAD and missing upstream remain representable states.
- Dirty untracked files appear without exposing ignored files.
- Failed checks appear as failures, never omitted or rewritten as success.
- Human checklist confirmations survive UI refresh but remain project-local.
- Draft generation escapes or preserves user-entered Markdown safely.

---

### Task 1: Git Fact Adapter

**Files:** Create `contribution/GtnhGitState.kt`, `compat/GitStateAdapter.kt`, `GtnhContributionService.kt`; add tests.

- [ ] Write failing tests for clean, dirty, detached, no-upstream, ahead/behind, and unavailable-Git states.
- [ ] Define immutable state with branch, worktree summary, remotes, upstream, ahead, behind, and changed paths.
- [ ] Read through public Git4Idea APIs in background tasks.
- [ ] Run tests; commit `feat: add contribution git diagnostics`.

### Task 2: Contribution Checks and Human Confirmations

**Files:** Create `GtnhContributionCheck.kt`, `GtnhContributionChecklistState.kt`, project-level persistent state; add tests.

- [ ] Write tests proving discovered Gradle checks are executable and human claims default false.
- [ ] Model observed automated checks separately from `DEV_ENV_TESTED`, `FULLPACK_TESTED`, and `AI_POLICY_ACKNOWLEDGED` confirmations.
- [ ] Persist only explicit user confirmation, never infer it from commands.
- [ ] Run tests; commit `feat: add contribution checklist`.

### Task 3: Truthful PR Draft Generation

**Files:** Create `GtnhPrDraftInput.kt`, `GtnhPrDraftService.kt`; test `GtnhPrDraftServiceTest.kt`.

- [ ] Write exact-output tests for no tests run, passing/failing checks, no issue, explicit issue, empty diff, and human confirmations.
- [ ] Render sections `Summary`, `Changes`, `Testing`, `Related Issues`, and `Checklist`.
- [ ] Emit `Fixes #N` only when input contains an explicitly associated issue and closing behavior was selected.
- [ ] Never infer DevEnv or Fullpack results from source changes.
- [ ] Run tests; commit `feat: generate truthful PR drafts`.

### Task 4: Contribution UI and Release

**Files:** Create `ui/GtnhContributionPanel.kt`, `ui/GtnhPrDraftDialog.kt`; modify Tool Window, version, changelog.

- [ ] Add refreshable Git facts, run-check actions, manual checkboxes, issue input, and editable draft.
- [ ] Keep generation local; provide copy action only.
- [ ] Set version `0.7.0`; run `test` and `buildPlugin`; commit `feat: add pull request assistant`.
