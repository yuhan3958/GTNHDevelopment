# v0.6 GTNH Ecosystem Navigation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Discover GTNH ecosystem dependencies and navigate their local APIs and examples without requiring network access.

**Architecture:** A dependency-source adapter normalizes Gradle module data. `GtnhDependencyService` classifies dependencies through providers and exposes immutable module-aware results. Navigation delegates to IntelliJ symbol/search APIs.

**Tech Stack:** Kotlin, Gradle project model, Java PSI indexes, IntelliJ navigation UI.

**Spec:** `docs/superpowers/specs/2026-09-23-gtnh-development-v1-design.md`

## Global Constraints

- Do not assume all GTNH projects use the same libraries.
- Do not clone repositories or require internet access.
- Preserve module ownership and resolved versions.

## Review Focus

- Same dependency in two modules remains distinguishable.
- Unresolved dependency versions appear as unknown without failure.
- Similar artifact names outside GTNH are not classified by substring alone.
- Missing attached sources still permit class navigation where bytecode PSI exists.
- Search remains project-scoped and cancellable.
