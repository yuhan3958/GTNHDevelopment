# v0.8 Safe GTNH Generation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate maintainable GTNH projects, Mixins, and config entries with previews and confidence-gated edits.

**Architecture:** Generators produce an immutable `GtnhGenerationPlan` before writing. Convention providers identify safe integration points with confidence. One apply service validates pointers and executes a single IntelliJ command after confirmation.

**Tech Stack:** Kotlin, IntelliJ New Project Wizard APIs, PSI factories, WriteCommandAction, diff preview.

**Spec:** `docs/superpowers/specs/2026-09-23-gtnh-development-v1-design.md`

## Global Constraints

- Reuse Minecraft Development public generation APIs when stable.
- Every multi-file change requires preview and confirmation.
- Low-confidence recognition never modifies existing source.

## Review Focus

- Invalid Java identifiers are rejected before plan creation.
- Existing files are never overwritten without an explicit replacement operation.
- Pointer invalidation between preview and apply aborts safely.
- Partial write failure remains one undoable command and reports affected files.
- Different repository conventions cannot be mixed in one plan.
