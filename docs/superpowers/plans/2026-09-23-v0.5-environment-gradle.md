# v0.5 Environment Doctor and Gradle Discovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace hardcoded task buttons with discovered Gradle tasks and add non-mutating GTNH environment diagnostics.

**Architecture:** Gradle model access is isolated behind `GtnhGradleTaskService`. Environment checks are independent and aggregated by `GtnhEnvironmentDoctor`. UI renders current immutable snapshots.

**Tech Stack:** IntelliJ External System, Gradle project data, Project SDK APIs, Git4Idea where public.

**Spec:** `docs/superpowers/specs/2026-09-23-gtnh-development-v1-design.md`

## Global Constraints

- Never shell out to Gradle for normal discovery/execution.
- Never mutate SDK, Gradle JVM, remotes, or build scripts automatically.
- Hide unavailable task actions.

## Review Focus

- Unsynced Gradle projects produce `UNKNOWN`, not crashes.
- Composite and multi-module builds preserve owning external project paths.
- Missing Git plugin or repository remains a valid diagnostic state.
- Java version comparison distinguishes runtime JVM from declared toolchains.
- Refresh/cancellation never leaves stale UI marked current.
