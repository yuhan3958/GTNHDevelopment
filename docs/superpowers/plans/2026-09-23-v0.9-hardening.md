# v0.9 Compatibility and Performance Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Harden settings, compatibility, caching, multi-module behavior, diagnostics, first-run UX, and supported-version verification.

**Architecture:** Central settings gate optional features. `compat` owns every version-sensitive boundary. Searches use measured, correctly invalidated caches. CI builds representative supported IDE/plugin combinations.

**Tech Stack:** IntelliJ PersistentStateComponent, CachedValue, Gradle matrix tasks, Plugin Verifier.

**Spec:** `docs/superpowers/specs/2026-09-23-gtnh-development-v1-design.md`

## Global Constraints

- `sinceBuild=251`, `untilBuild=262.*`.
- No scattered IDE build-number checks.
- Correctness precedes caching.
- No repeated first-run notifications.

## Review Focus

- Settings migration preserves defaults when fields are absent.
- Cache invalidation covers Java, resources, Gradle sync, and module changes.
- Composite builds retain correct search and task scopes.
- Indexing disables/defer features without stale enabled actions.
- Unsupported adapters fail closed with actionable diagnostics.
